# 5-Stage Pipelined RV32I RISC-V CPU Core

A complete, synthesizable, IEEE 1800-2017 **SystemVerilog** implementation of a **5-Stage Pipelined RV32I RISC-V Processor Core** with hardware data forwarding, load-use hazard detection, branch control flushing, a custom Python assembler, and an automated verification suite.

---

## 🏛️ Microarchitecture Overview

```
 +-------------+    +-------------+    +-------------+    +-------------+    +-------------+
 |   IF Stage  | -> |   ID Stage  | -> |   EX Stage  | -> |  MEM Stage  | -> |   WB Stage  |
 | PC + Imem   |    | Regfile+Decoder| | ALU + MUXes |    | Data Memory |    | WB Write MUX|
 +-------------+    +-------------+    +-------------+    +-------------+    +-------------+
        ^                  |                  ^                  |                  |
        |                  v                  |                  v                  |
        +---------------------------------------------------------------------------+
                                  Hazard & Forwarding Unit
```

### Pipeline Stages
1. **Instruction Fetch (IF)**:
   - Program Counter (PC) with stall capability.
   - Branch target MUX ($PC + 4$ vs Branch/Jump target address).
   - Instruction Memory Interface.
2. **Instruction Decode (ID)**:
   - 32 x 32-bit Dual-Read, Single-Write Register File (`x0` hardwired to 0).
   - Control Unit decoding R-Type, I-Type, S-Type, B-Type, U-Type, and J-Type instructions.
   - Sign-Extension Immediate Generator (I, S, B, U, J format immediates).
3. **Execute (EX)**:
   - 32-bit Arithmetic Logic Unit (ALU) supporting `ADD`, `SUB`, `SLL`, `SLT`, `SLTU`, `XOR`, `SRL`, `SRA`, `OR`, `AND`.
   - Operand Forwarding MUXes for EX->EX and MEM->EX hazard resolution.
   - Branch condition evaluator and branch target calculation.
4. **Memory Access (MEM)**:
   - Byte/Halfword/Word store alignment (`SB`, `SH`, `SW`) with byte-enables.
   - Byte/Halfword/Word load sign/zero extension (`LB`, `LBU`, `LH`, `LHU`, `LW`).
5. **Writeback (WB)**:
   - Final MUX selecting between ALU result, Data Memory read data, and $PC + 4$.

### Hazard Handling Unit
- **EX->EX Forwarding**: Forwards ALU result directly from EX/MEM pipeline register to EX ALU operands.
- **MEM->EX Forwarding**: Forwards data from MEM/WB pipeline register to EX ALU operands.
- **Load-Use Hazard Stalling**: Detects when an instruction in Decode depends on a `LW` instruction in Execute; inserts a 1-cycle stall bubble into IF/ID and freezes PC.
- **Control Hazard Flushing**: Flushes IF/ID and ID/EX pipeline registers upon taking a branch or jump (`BEQ`, `BNE`, `BLT`, `BGE`, `BLTU`, `BGEU`, `JAL`, `JALR`).

## 📁 Repository Structure

```
riscv-5stage-pipeline/
├── rtl/
│   ├── rv32i_pkg.sv          # SystemVerilog package (opcodes, funct3/7, structs)
│   ├── fetch_stage.sv        # Instruction Fetch (IF) stage
│   ├── decode_stage.sv       # Instruction Decode (ID) stage wrapper
│   ├── register_file.sv      # 32x32 Register File with x0=0
│   ├── control_unit.sv       # Instruction Decoder & Control logic
│   ├── imm_gen.sv            # Immediate Sign Extender
│   ├── execute_stage.sv      # Execute (EX) stage with forwarding MUXes
│   ├── alu.sv                # 32-bit Arithmetic Logic Unit
│   ├── memory_stage.sv       # Data Memory (MEM) access & formatting stage
│   ├── writeback_stage.sv    # Writeback (WB) MUX stage
│   ├── hazard_unit.sv        # Hazard Detection & Forwarding Unit
│   ├── pipeline_registers.sv # IF/ID, ID/EX, EX/MEM, MEM/WB registers
│   └── rv32i_core.sv         # Top-level RISC-V Core module
├── tb/
│   ├── ram_memory.sv         # RAM module preloaded with machine code (.hex)
│   └── tb_rv32i_core.sv      # SystemVerilog Testbench for simulation
├── tools/
│   ├── assembler.py          # RISC-V RV32I Assembler
│   └── test_runner.py        # Python Reference Model & Test Suite
├── tests/
│   ├── test_arithmetic.s     # R-Type and I-Type ALU assembly tests
│   ├── test_hazards.s        # Data forwarding and Load-Use stall tests

│   └── test_memory.s         # Byte/Halfword/Word load & store tests
└── README.md
```

## 🚀 How to Run Simulation

### Option 1: Xilinx Vivado (GUI or Batch)
1. Open **Vivado** and create a new **RTL Project**.
2. Select **SystemVerilog** as the target language.
3. Add all files in `rtl/` under **Design Sources**. Set `rv32i_core.sv` as Top Module.
4. Add `tb/ram_memory.sv` and `tb/tb_rv32i_core.sv` under **Simulation Sources**.
5. Copy `imem.hex` (generated by `assembler.py`) into the Vivado project root.
6. Click **Run Simulation** $\rightarrow$ **Run Behavioral Simulation**.
7. Observe internal pipeline registers (`IF/ID`, `ID/EX`, `EX/MEM`, `MEM/WB`), hazard signals (`forward_a`, `forward_b`, `stall_if`, `flush_ex`), and register file (`x0` - `x31`).

### Option 2: Icarus Verilog (`iverilog`) & GTKWave
Run the following command in your terminal:
```bash
# Assemble a test file into imem.hex
python tools/assembler.py tests/test_arithmetic.s imem.hex

# Compile SystemVerilog sources
iverilog -g2012 -o rv32i_sim.vvp rtl/*.sv tb/*.sv

# Run simulation
vvp rv32i_sim.vvp

# Open waveform in GTKWave
gtkwave waveform.vcd
```

### Option 3: Python Automated Reference Test Suite
Run the python reference test suite directly from your terminal:
```bash
python tools/test_runner.py
```

## ⚡ Hardware Synthesis Guidelines for Vivado
- **Top Module**: `rv32i_core`
- **Target Architecture**: Artix-7 / Kintex-7 / Zynq-7000 / UltraScale+
- **Block RAM**: Vivado automatically infers Block RAM (BRAM) for `ram_memory.sv`.
- **Clocking**: Supports clock rates $\ge 50 \text{ MHz}$ depending on target FPGA grade.
